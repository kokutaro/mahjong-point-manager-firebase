# 点数計算・対局進行・精算の仕様

## 概要

和了・流局の入力に応じて点数と局を進め、終局時に順位と精算ポイントを求める。3人打ちと4人打ちで支払いを分け、通常の部屋と大会で同じ計算処理を使う。

## 1. 和了は翻・符または満貫以上の区分から入力する

| ID      | 現行動作                                                                                                                                                                    |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-101 | 利用者がロン／ツモ、和了者、ロン時の放銃者を指定し、各和了者の打点を入力して確定する。複数ロンは和了者ごとに入力する                                                        |
| BR-101  | 符計算ありでは1〜4翻と20・25・30〜110符の選択肢を基本とする。1翻は30符以上、3翻は70符以上、4翻は40符以上をまとめて選ぶ。満貫・跳満・倍満・三倍満・役満〜4倍役満は直接選べる |

符計算ありの基本点は `符 × 2^(翻 + 2)`。通常の打点は基本点2,000で満貫を上限とし、5翻は満貫、6〜7翻は跳満、8〜10翻は倍満、11〜12翻は三倍満、13翻以上は役満単位となる。4翻30符と3翻60符を満貫へ切り上げる設定はない。

符計算なしでは、1〜3翻に次のロン点を使う。値は部屋・大会設定から変更でき、旧データでは既定値を補う。4翻は計算処理では満貫として扱い、画面では満貫の直接選択を使う。

| 翻  | 子    | 親    |
| --- | ----- | ----- |
| 1翻 | 1,000 | 1,500 |
| 2翻 | 2,000 | 3,000 |
| 3翻 | 4,000 | 6,000 |

通常計算のロンは子が基本点の4倍、親が6倍。ツモは親の和了なら各子が基本点の2倍、子の和了なら親が2倍、他の子が1倍を支払う。各支払いを100点単位で切り上げる。固定点からのツモは、親ならロン点の3分の1、子なら親が2分の1、他の子が4分の1を基準に、同じく切り上げる。

3人打ちのツモでは、4人目が払うはずの額の半分を100点単位で切り上げ、残る2人の支払いへそれぞれ加える。例えば子の満貫ツモは、親5,000点・子3,000点。親の満貫ツモは各子6,000点となる。

## 2. 本場・供託・複数ロン・チップ

| ID      | 条件と現行動作                                                                                                                                                       |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-102 | リーチ可能な参加者を利用者が指定すると1,000点を引き、供託を1本増やす。和了時に供託を渡し、流局では持ち越す                                                           |
| BR-102  | リーチボタンは持ち点1,000点以上かつ未リーチの場合に有効。和了または流局で各人のリーチ状態を解除する                                                                  |
| BR-103  | ロンの本場点は1本につき300点を放銃者が支払う。ツモは人数にかかわらず各支払い者が1本につき100点を払う。複数ロンでは入力結果の先頭の和了者だけが本場点と供託を受け取る |
| REQ-103 | チップ使用時、利用者が和了ごとの枚数を入力すると、ロンは放銃者から、ツモは各相手から指定枚数を移す                                                                   |

旧仕様の「放銃者から見た順序で本場・供託を渡す」というルールに対し、現在は席順による並べ替えを行わない。三家和による流局と有効ロンの切り替えもない。Q-103 で判断する。

設定 `honbaPoints` は保存されるが、上記の点数移動では使わない。3人打ちの既定設定1,500点も支払いへ反映されないため、設定どおりに動くとは扱わない（Q-101）。

## 3. 流局・親の交代・延長

| ID      | 現行動作                                                                                                                                                                                              |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-104 | 利用者が流局時のテンパイ者を選ぶとノーテン罰符を移し、連荘設定に従って次の局へ進める                                                                                                                  |
| BR-104  | 4人打ちは計3,000点をノーテン者からテンパイ者へ均等配分する。3人打ちはノーテン者1人がテンパイ者1人につき1,000点を払う。全員テンパイ・全員ノーテンは点数移動なし                                        |
| BR-105  | 和了者に親を含めば連荘。子だけの和了は親を交代して本場を0にする。流局はテンパイ連荘が有効で親がテンパイなら連荘し、それ以外は親を交代する。本場有効時、連荘と流局で本場を1増やす。本場無効時は0とする |

親の交代に合わせて各人の風を巡回させる。局番号は4人打ちで1〜4、3人打ちで1〜3。場は東→南→西→北→東と進み、北から東へ戻ると周回数を増やす。

流局入力には「途中流局」の切り替えがあり、選ぶとテンパイ者の選択を解除して点数移動を0にする。ただし保存時はテンパイ者なしの通常流局として渡すため、親は交代し、本場有効なら1本増える。理由の記録や途中流局専用の連荘判定はない。九種九牌や四風連打の扱いは Q-104 で決める。根拠は[流局入力](../src/components/features/RyukyokuBoard.tsx)。

## 4. 自動終了と途中終了

| ID      | 条件と現行動作                                                                                                                                                                               |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-105 | 和了・流局後にトビ、規定場の終了、親の終局条件を判定し、成立すれば対局結果を保存して対局終了状態へ進める                                                                                     |
| BR-106  | トビ有効なら持ち点が0点未満で終了する。0点ちょうどでは終了しない。半荘は南場、東風戦は東場の終了以降、場が切り替わる時に誰かが返し点以上なら終了する。返し点未到達でも延長が無効なら終了する |
| REQ-106 | 利用者が途中終了を選ぶと、成績に残す／残さないを選べる。残す場合は現時点の点数から結果を作り、途中終了の印を付ける                                                                           |

延長が有効で全員が返し点未満なら次の場へ進む。北場の次も東場へ巡回でき、返り東以降は各場の終了時に同じ条件を判定する。延長中の各局で、返し点到達だけを理由に終局する処理はない。

親の終了条件は南4局（3人打ちは南3局）での連荘時に判定する。親が単独トップかつ返し点以上なら自動終了するため、和了だけでなくテンパイ連荘も対象となる。本人が続行を選ぶ操作はなく、東風戦の東場最終局にはこの判定を適用しない（Q-105）。

途中終了では、残った供託を終了前の1位へすべて渡し、リーチ状態と進行中ログを解除する。結果を残さない場合も供託は移す。通常の部屋ではホスト用、大会では主催者・共同主催者用の操作として表示する。自動終了の残供託とは処理が異なる（Q-106）。

## 5. 点数調整と取り消し

| ID      | 条件と現行動作                                                                                                                                                                                                  |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-107 | 通常の部屋で利用者が支払い元1人、受取先1人以上、1人当たりの額、任意の理由を指定し、点数を移せる。直前の記録操作を取り消せる                                                                                     |
| BR-107  | 調整額は正の整数かつ100点単位。支払い元と受取先は対局者から選ぶ。支払い元と受取先が同じ場合、受取先が重複する場合、受取先がない場合は拒否する。点数調整では局・本場・供託・リーチ状態を変えず、トビ判定もしない |

調整は局ログへ `Adjustment` として残す。和了、流局、リーチ、点数調整の操作前状態を保存し、取り消しでは直前の状態と結果・ログを戻して、点数変動イベントを消す。対局開始、次戦への移行、途中終了を、同じ取り消し機能の対象として保証しない。同時操作との整合は共通仕様の Q-002 に従う。

効果音は通常の部屋・大会卓で個別に有効化する。初期状態は無効。新しいリーチ・ロン・ツモのイベントで再生し、入室時に取得した過去のイベントは再生しない。流局・調整・取り消しには音の指定がない。ブラウザの再生制限で音が出ない場合も、記録処理は継続する。

## 6. 順位と精算ポイント

| ID      | 条件と現行動作                                                                                                                                                                                                                                                 |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-108 | 対局終了時に順位・素点・精算ポイントを記録し、結果画面で対局別と累計を確認できる。通常の部屋の終了時にはレートを使った精算値を表示する                                                                                                                         |
| BR-108  | 持ち点降順で順位を付け、同点は参加者配列の先頭を優先する。2位以下は持ち点を1,000で割り、返し点未満なら切り上げ、それ以外は切り捨てて、返し点÷1,000を引く。1位のポイントは、2位以下のポイント合計の符号を反転した値とする。その後、各人へウマと焼き鳥分を加える |
| DAT-101 | 対局結果は順位・素点・ポイント・チップ収支欄・当時の設定・局ログを持つ。焼き鳥はその対局の和了者集合で判断し、過去対局の和了は使わない                                                                                                                         |

ウマを `[小, 大]` とすると、4人打ちは1位から `+大、+小、−小、−大`、3人打ちは `+大、0、−大`。「なし」なら全員0となる。

焼き鳥有効時、一度も和了していない人が、和了した各人へ設定分の精算ポイントを支払う。対局終了時に1回だけ適用し、持ち点と順位は変えない。全員未和了なら支払いなし。未設定データは無効・10ポイントとして扱う。

通常の部屋の最終精算表示は `四捨五入((対局ポイントの累計 + 現在のチップ) × レート)`。金銭の送受信は行わない。設定 `useOka` と `chipRate` はこの計算の切り替えに使われず、対局結果の `chipDiff` は常に0で作られる。このため、大会・シリーズのチップ集計欄にも実際のチップ移動が反映されない（Q-102）。
