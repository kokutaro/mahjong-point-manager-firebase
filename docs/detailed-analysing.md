# 詳細分析ノートの仕様

## 概要

自分の和了・放銃・テンパイ流局を履歴から選び、手牌や待ち、ドラ、気づきを個人の分析ノートに残す。対局直後でも、保存済みの履歴からでも入力できる。

| 項目             | 内容                                                                                                                                                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象システム／ID | `mahjong-point-manager`／FNC-006                                                                                                                                                                                                        |
| 状態             | 草案。旧仕様の役入力等と現行画面に差異あり                                                                                                                                                                                              |
| 共通仕様         | [製品仕様](specification.md)                                                                                                                                                                                                            |
| 根拠             | [分析の型](../src/types/analysis.ts)、[分析処理](../src/utils/analysis.ts)、[ノート保存](../src/services/analysisService.ts)、[入力画面](../src/components/features/AnalysisDetailModal.tsx)、[一覧](../src/pages/AnalysisListPage.tsx) |

入力・閲覧・編集・削除が対象。役・待ちの頻度集計、分析グラフ、ノートの共有・公開、画像からの手牌認識、ノートの CSV 出力は現在の対象外とする。既存の対戦ダッシュボードとは別の機能である。

## 1. 本人に関係する局を選ぶ

| ID      | 条件と現行動作                                                                                                                                     |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-301 | 利用者が通常の部屋・大会卓・履歴詳細にある対象イベントを選び、分析ノートを作成または再編集できる。和了・流局の記録後にも入力への案内を表示する     |
| BR-301  | 対象は本人の和了、本人の放銃、本人がテンパイした流局。点数調整と、本人が関係しない他家の和了は対象外。イベント種別は局ログから決め、手動変更しない |
| REQ-302 | 既存のノートを開いた場合は保存内容を使い、未保存なら局情報・自風・リーチ状態・取得可能な翻・符を初期値にする                                       |

空のイベントを手動で作る機能はない。ノートは元の局ログに紐付ける。[イベント構築処理](../src/utils/analysisEvents.ts)は進行中ログと保存済み結果から本人の対象局を取り出す。大会の結果を使う場合は、参加者 ID と認証 UID の関係も解決する。

現在の入力導線は通常の対局画面、大会卓画面、履歴詳細、分析ノート一覧。旧仕様にあった単大会レポート上の分析対象一覧は、現在の [CompetitionReportPage](../src/pages/CompetitionReportPage.tsx) にはない。大会の部屋の履歴詳細や卓画面から参照する。

## 2. 手牌は文字で入力し、牌画像で確認する

| ID      | 条件と現行動作                                                                                                                                |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-303 | 利用者が文字による牌姿表記を入力すると、手牌・副露・和了牌と入手元を解釈し、牌画像を表示する。ドラ表示牌4種も文字で入力できる                 |
| BR-302  | 手牌は種類を示す `m`（萬子）・`p`（筒子）・`s`（索子）・`z`（字牌）の後に数字を置く。赤5は `5r`。字牌は1〜7で東・南・西・北・白・發・中を表す |

入力例は `m123p456s789z11122`。表示用の表記は種類記号を先に置く。内部の牌コード `1m` や赤5の `0m` を、そのまま入力形式とは扱わない。

和了牌は末尾の牌に `_` を添えてツモを表す。ロンの入手元は `-` が下家、`=` が対面、`+` が上家。副露はカンマで区切り、チー・ポン・明槓・暗槓・加槓を表せる。表記の詳細と境界は[牌姿表記の設計](design/hai-expression.md)を参照し、変換処理と一致しない例は Q-303 で扱う。

ドラ表示牌、裏ドラ表示牌、槓ドラ表示牌、槓裏ドラ表示牌を別に持ち、画面入力は各4枚まで。構文不正や上限超過は入力欄に表示し、正常に解釈できた最後の値を保持する。保存処理は入力エラーの存在だけでは停止しないため、不正な文字列そのものを保存する機能ではない。

## 3. 待ちを自動判定し、入力が未完成でも保存する

| ID      | 条件と現行動作                                                                                                                                                   |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| REQ-304 | 手牌から待ち牌と待ち分類を自動判定し、ノートに保存する。安全に判定できない場合は未判定とする                                                                     |
| BR-303  | 和了・放銃の記録では和了前の手牌を使い、テンパイ流局ではその手牌を使う。赤5を通常の5として判定し、両面・三面・辺張・嵌張・シャボ・単騎・延べ単騎・変則に分類する |
| REQ-305 | 利用者が立直状態、一発、海底・河底・嶺上・槍槓と自由記述を編集し、未完成でも保存できる                                                                           |
| BR-304  | 牌数や和了牌の不足は警告とし、保存を妨げない。自由記述は前後の空白を除き、保存時に最大2,000文字へ切り詰める                                                      |

待ちの判定は[待ち計算](../src/utils/waits.ts)による。空の手牌は待ち未入力、枚数不足や和了牌なしなどは未判定として区別する。標準形に加え、七対子と国士無双も判定対象。役の成立、フリテン、山に残る枚数まで保証する機能ではない。

保存済みの待ちは閲覧時にそのまま表示する。手牌を変えずにメモだけ保存しても再計算しない。牌の並び替え、赤5の同一視、和了牌の入手元だけの変更など、判定上同じ手牌なら保存済み結果を維持する。旧形式の待ち分類も読み込み、牌の詳細がない場合は分類だけを表示する。

牌数の目安は、手牌・副露・和了牌を合わせて和了・放銃では14枚、テンパイ流局では13枚とし、それぞれに槓の数を加える。放銃時も本人視点の手牌として入力する。

旧仕様にあった役・役満の一覧選択、赤5枚数の数値入力、翻・符の手動編集は、現在のモーダルにない。型と既存値は残っているが、画面から編集できる項目とは分けて扱う（Q-301）。翻・符の初期値も通常表記と固定点表記から取得できる場合に限り、満貫等の名称から役や符を推定しない。

## 4. 一覧から閲覧・再編集・削除する

| ID      | 条件と現行動作                                                                                                                   |
| ------- | -------------------------------------------------------------------------------------------------------------------------------- |
| REQ-306 | 利用者が分析ノート一覧を開くと、本人のノートを更新日時の新しい順に表示する。期間とイベント種別で絞り込み、閲覧・編集・削除できる |

期間はすべて・7日以内・30日以内・90日以内で、更新日時を基準にする。行には局、種別、通常／大会の区分、更新日時、メモ、保存済みの役・役満の先頭2件を表示する。

閲覧モードは変更不可。編集モードは保存・キャンセル・削除を使える。保存・削除中は重複操作を抑止する。キャンセルでは保存データを変更しない。削除するのは個人のノートだけで、共有の局ログや対局結果は残す。

## 5. 個人データの保存と権限

| ID      | データ要件                                                                                                                                                            |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DAT-301 | 本人の UID ごとに、元の局 ID、局情報、手牌・副露・和了牌と入手元、待ち、4種のドラ表示牌、和了条件、メモ、作成・更新日時を保持する。同じ局のノートは1人につき1件とする |

保存 ID は元の局ログ ID と一致させる。同じ局を保存すると同じノートを更新し、不要になった和了牌・入手元や旧形式の待ち欄は削除する。共有の局ログには詳細な手牌を追記しない。

本人だけが読み書き・削除でき、匿名認証でも同じ UID に対して利用できる。別アカウントの個人ノートは表示しない。認証の切り替え時は取得状態を切り替え、同じ UID での再ログイン時も読み直す。メール登録で UID を維持する場合は継続利用できるが、別 UID への引き継ぎ処理にはノートを含まない（認証仕様の Q-201）。

## 6. 非機能条件と関連設計

共通のオンライン条件・個人データの認可・モーダル操作は[共通仕様](specification.md#6-共通データ非機能要件と制約)に従う。牌画像は同梱の SVG を共通部品で重ねて描画し、暗槓の裏面や副露の横向き表示にも対応する。オフライン入力の保証はない。

設計資料は[牌姿表記](design/hai-expression.md)、[内部設計](internal_design.md)。ノートの容量、応答時間、保存期間の合意値はなく、共通の Q-003 に含める。
